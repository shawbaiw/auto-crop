# Modern Dashboard UI Foundation

The dashboard is moving away from CRT and retro styling because those effects add visual noise and cognitive load to the founder-facing workbench. New dashboard UI will use Tailwind as the primary component styling path, shadcn/Radix-derived components as a source for basic accessible interactions, and product-specific components for core experiences such as the AppShell, workspace surfaces, task flow, and composer input. Existing Retro UI and CRT effects remain migration scaffolding, not the target design system.

Cumora is the primary reference for the overall modern workbench language: clean surfaces, soft borders, restrained shadows, and low visual noise. DeepWiki is a narrower reference for the composer input treatment, not a page-wide glassmorphism direction.

The first migration slice is Company Picker, Onboarding, and Creation Loading. The dashboard will start with one light modern theme; the old multi-skin palette system and CRT effect are not future user-facing options. After migration, `styles.css` should shrink to Tailwind imports, global reset, CSS variables, and a small set of global rules rather than remaining the main component stylesheet.

shadcn setup belongs inside `apps/dashboard`, not at the monorepo root and not in a premature `packages/ui`. The dashboard is the only current consumer, so `apps/dashboard/components.json`, dashboard-local Tailwind config, `apps/dashboard/src/components/ui`, and `apps/dashboard/src/lib/utils.ts` are the right starting boundary. Extracting a shared UI package should wait until there is a second real frontend consumer.

The modern theme uses shadcn-compatible token names such as `--background`, `--foreground`, `--card`, `--primary`, `--muted`, and `--border`. Legacy tokens such as `--field`, `--ink`, and `--surface` may remain only for legacy Retro UI during migration. `src/components/ui` is reserved for low-level shadcn-style primitives; product components should live in semantic areas such as `src/components/workbench`, `src/components/composer`, or `src/components/company-flow`.

Complex accessible interactions such as Dialog, Popover, Dropdown, Select, Tabs, Tooltip, and Command should prefer shadcn/Radix-derived primitives instead of new hand-rolled behavior. Creation Loading should become a calm progress surface with lightweight status/timeline presentation, not a CRT terminal or brand animation. Onboarding remains a step-by-step wizard, redesigned with the modern UI language. Once a page no longer references legacy Retro UI or CRT files, remove the unused legacy files in that slice after verifying references.

Implementation should start with a dashboard-local foundation slice: Tailwind/shadcn configuration, modern tokens, primitive UI components, and a reusable modern AppShell skeleton. That AppShell should be broad enough to later host the main workbench, but its first version only needs to support Company Picker, Onboarding, and Creation Loading. `lucide-react` remains the default icon set.

The first page migration is complete when functionality remains intact, the migrated pages no longer render CRT or Retro UI components, and desktop and mobile screenshots show the modern layout working without obvious visual regressions. Dark mode is intentionally out of scope for the first version, though token naming should not block it later. Existing Interface Locale and Localized Business Content rules remain in force; UI redesign does not permit temporary hard-coded English system text.

The foundation slice should be assembled manually rather than delegated to the shadcn CLI guessing the monorepo shape. It should create the dashboard-local config and utilities, then add only the first primitives needed by the initial migration: Button, Input, Textarea, and Label. Additional Radix-backed primitives should be added when a migrated page actually needs them. A foundation or page slice is not complete until dashboard typecheck, dashboard tests, and dev-server screenshot inspection pass. During active migration a page may temporarily mix modern and Retro UI, but a delivered page slice must be either still legacy or fully modern, not half-and-half.
